# **Color Mixing Studio Webアプリ機能仕様書**

## *仕様版 1.0　作成日 2026年10月11日　対象 開発担当者と品質評価担当者*

12種類の独自ルックを連続的に混ぜ、写真と動画をグレーディングし、設定とLUTを制作環境へ持ち出せるブラウザアプリを定義する。中核はHybrid Color Mixing Engineとし、多項式の係数合成、OKLabによる知覚補正、Subtractive Densityを組み合わせる。写真編集を最初の正式リリースとし、動画とResolve連携の機能契約も本書に定める。

本書の画面構成、数値範囲、混色式、独自ルック、品質基準は本アプリの設計仕様である。Monetの係数、名称、プリセット、画面資産を流用せず、元製品と同じ色を保証する互換製品にはしない。

# **1 製品の目的と完成条件**

ユーザーは「好きなルックを選ぶ」「複数のルックを混ぜる」「強さと色の濃さを調整する」「比較する」「保存する」の順で作品を仕上げられる。専門的なノード構築をしなくても混色でき、上級者は処理空間と書き出し契約を確認できる。

正式リリースの完成条件は、12ルックの単独使用と任意の同時混色、破壊的でない編集、再現可能な保存、元解像度の画像出力、33および65格子のLUT出力、UndoとRedo、色管理と品質試験の合格である。画面だけ動くデモを完成品として扱わない。

画像の見栄えは、肌、ニュートラル、高彩度色、ハイライトの質感、暗部の階調、露出の異なる画像で評価する。色差の小ささは計算の再現性評価に使い、創作ルックの美しさを色差だけで判定しない。

# **2 調査から採用する設計判断**

Monetの公開説明では12種類のカラーを混合するDCTLという製品思想を確認できる。\[R1\] 多項式処理の詳細、全パラメータ値域、各色の係数は本アプリの独自定義とする。

OKLabは明度、色相、クロマを分離して扱う補助空間として採用する。\[R2\] 全ルックをOKLabで平均することや、顔料を物理的に混ぜることを中核処理と同一視しない。

Root Polynomialの研究は通常の多項式による露出依存を抑える参考になる。\[R3\] 本アプリのフィルム調のトーン変更まで露出不変になるという保証には使わない。初期の創作変換は有界なSDRルック領域の多項式とし、Root Polynomialは別途検証する。

学習された基底LUTを係数で合成する研究を、複数変換を事前合成して画素処理を軽くする参考とする。\[R4\] 初期製品には自動学習や画像内容による混合量の自動変化を入れない。

BlackmagicのColorSliceの減法的な彩度操作は、彩度を上げるだけでなく色の濃さを作るという操作設計の参考とする。\[R5\] 密度の計算自体は本書の独自モデルであり、実測フィルムの光学濃度ではない。

ACES 2の出力変換は、トーン、クロマ、色域の処理を分離する参考とする。\[R6\] OKLabはACES 2のJMhと異なる。独自のSDR色域圧縮をACES準拠と表示しない。入力側のReference Gamut Compressionと出力側の色域圧縮も別処理として扱う。\[R7\]

メイン画面は上部ツールバー、左の素材とプリセット、中央プレビュー、右の調整パネル、下部スコープで構成する。左と下は折りたたみ可能。右の混色パネルは常に到達しやすい位置に保つ。

| 領域 | 表示と操作 |
| :---- | :---- |
| ツールバー | 読み込み、保存状態、Undo、Redo、比較、出力、ヘルプ |
| 左パネル | 素材一覧、プリセット検索、お気に入り、スナップショット |
| 中央 | プレビュー、ズーム、表示範囲、比較ラベル、読み込み状態 |
| 右パネル | 基本補正、12色ミキサー、知覚補正、Creative、質感 |
| 下パネル | Histogram、RGB Parade、Waveform、Vectorscope、P2タイムライン |
| 設定画面 | 表示空間、キャッシュ、保存先、対応機能、言語、バージョン |

数値入力、スライダー、左右キー、Shift付きの微調整を共通提供する。ダブルクリックで項目の既定値へ戻す。各処理グループに有効切替とグループリセットを設ける。全リセットはUndo可能。数値の入力確定はEnter、取り消しはEscape。

スライダーのドラッグ中は連続プレビューし、履歴へはドラッグ終了時に1件を追加する。入力途中の空文字やマイナス記号は確定値にしない。確定した範囲外の値は上限または下限へ収め、修正された値を表示する。NaN、Infinity、未知のenumは拒否する。

# **6 素材読み込み**

FR-IMP-01 ファイル選択とドロップを提供する。複数ファイルは素材一覧へ追加し、最初の有効なファイルを選択する。1件の失敗で他の読み込みを止めない。MIMEとシグネチャを確認する。

FR-IMP-02 P1は静止JPEGとPNGに限定する。GIF、APNG、HEIC、AVIF、RAW、TIFFは対応済みと表示せず、変換先としてsRGB JPEGまたはPNGを案内する。アニメーションPNGは検知して拒否する。

FR-IMP-03 EXIFの向きを一度だけ適用し、内部画像は表示方向に正規化する。画像サイズ、入力形式、ICC状態、アルファ有無を素材情報に表示する。透明画素はstraight alphaとして処理し、色変換後に必要な表示合成を行う。

FR-IMP-04 P1の入力はsRGBを必須とする。sRGBタグ付き素材は受け入れ、タグなしは「sRGBとして扱う」と明示して読み込める。未知または広色域ICCは無言でsRGB扱いせず、対応デコーダがなければ停止する。ブラウザがICCを適用した結果へ再度ICC変換をかけない。

FR-IMP-05 8bitと16bit PNGを区別する。16bit PNGを8bitにデコードする経路しかない環境では「編集入力は8bitに変換」と読み込み前に表示する。16bit保持を製品の初期保証に含めない。

FR-IMP-06 製品上限は写真1枚100MiB、40メガピクセル、100素材／プロジェクトとする。これらは受入上限で、端末のメモリ不足時の成功保証ではない。デコード前に寸法を取得し、巨大画像を事前検知する。

プレビューは長辺2048pxを標準、ドラッグ中は長辺1024pxまで動的に低減する。元画像の画素を保持し、書き出し時は元解像度をタイル処理する。読み込み中のキャンセルでデコード、サムネイル、GPU資源を解放する。

# **7 色管理と処理順序**

P1のルック処理はdisplay referredのSDR処理である。入力sRGBを一度デコードしたlinear sRGBを用い、白点D65、通常の画素領域0から1を基準とする。Exposureを撮影時の露光再現とは表示しない。

処理順序は固定し、ユーザーがノードを並び替える機能は提供しない。P1は次の順で処理する。

1\. 入力検査、向き補正、ICC処理とアルファ分離。

2\. sRGBの伝達関数をデコードしlinear sRGBへ変換。

3\. Exposure、WB、Pre Contrast、Pre Saturation。

4\. 基本補正で領域外へ出た値を基準SDR領域へ滑らかに収める。

5\. 12基底ルックの多項式混色と知覚保護。

6\. Blue Yellow、Green Purple、Density、Aging、Filmic、Fade、Highlight Roll。

7\. Post SaturationとVibrance、最終の色域圧縮。

8\. 質感処理、アルファ再合成、表示空間への変換と伝達関数の適用。

9\. 表示またはエンコード。スコープは選択した処理段階から計算。

処理途中はfloat32計算を基準とする。最終出力の量子化以外で0から1への単純なハードクリップを繰り返さない。CPU参照、GPU、LUT生成は同じ処理定義を用いる。数値安定化のepsilonはエンジン定数として保存する。

P2のシーン入力は入力伝達関数と原色を明示してシーン線形へ変換し、ExposureとWBをそこで行う。検証済みの基準レンダリングでSDRルック領域へ移した後、本アプリの創作処理を行う。ACES 2を使う場合は版とTransform IDを保存し、基準レンダリングを二重に適用しない。既にレンダリング済みのJPEGにシーン用トーンマッピングを重ねない。

P2の候補入力は検証済みのSony S Log3とS Gamut3 Cine、Panasonic V LogとV Gamut、DaVinci Wide GamutとIntermediateである。自動判定は候補提示に留め、メタデータがない素材のLog種類を色の見た目だけで確定しない。

HDRはP1とP2のSDRエンジンをそのまま拡張して提供しない。JMhなどを含む専用の知覚処理、出力ピーク輝度、PQとHLGのエンコード、10bit保持、モニター検証を別途要求する。SDRへの変換だけできる状態をHDR編集対応と呼ばない。

# **8 12色ミキサー**

FR-MIX-01 12枚のルックカードを表示する。各カードは名前、色傾向、現在画像の単独適用サムネイル、重みスライダー、数値、有効、ソロ、ロックを持つ。カードの色チップは識別用で、全画像がその単色になることを意味しない。

FR-MIX-02 各重みは0から100、既定0、UI刻み1、内部は小数を保持する。全体強度は0から100%、既定100%。重みは比率であり、混合比率と効果の強さを別々に制御する。

FR-MIX-03 有効かつ重みが正のカードだけで比率を正規化する。全色ゼロでは強度に関わらず恒等変換。一色だけ有効なら、その重みが1でも100でも、全体強度100%では同じ単独ルックになる。小さい重みを薄い適用と誤解させないよう比率表示を添える。

FR-MIX-04 例としてAmber 30、Moss 70なら30%対70%。両方100なら50%対50%。このとき全体強度40%は元画像60%と混合ルック40%を混ぜる。すべての重みを同じ倍率で変えても見た目は変わらない。

FR-MIX-05 有効切替は重みを残したまま混色から除外する。ソロは比較用の一時状態とし、保存、LUT、出力へ含めない。ソロ中に出力すると保存状態へ戻ることを表示する。複数ソロは許さない。

FR-MIX-06 ロックはNuanceによる変更と「比率を均等にする」の対象外にする。手動操作は許可する。合計100に収める操作は有効な重みを等倍に変換するだけで、見た目を変えない。カード表示順は計算結果に影響しない。

## **8 1 規範となる混色アルゴリズム**

次の疑似コードを機能契約とする。coefficientsは共通基底を使う3行20列の係数行列。neutralCoefficientsは入力をそのまま返す係数行列である。

active \= \[i for i in looks if enabled\[i\] and weight\[i\] \> 0\]  
total \= sum(weight\[i\] for i in active)  
if total \== 0 or masterStrength \== 0:  
    mixed \= inputRGB  
else:  
    ratio \= {i: weight\[i\] / total for i in active}  
    base \= sum(ratio\[i\] \* coefficients\[i\] for i in active)  
    effective \= ((1 \- masterStrength) \* neutralCoefficients  
                 \+ masterStrength \* base)  
    mixed \= effective @ basis(inputRGB)  
masterStrengthは内部値0から1。基底は定数、R、G、B、2次6項、3次10項からなる総次数3以下の20項とする。入力は第7章の有界ルック領域。係数合成は設定変更時に行い、画素ごとに12個の完全な処理を実行しない。

basis \= \[1, R, G, B, R\*R, G\*G, B\*B, R\*G, R\*B, G\*B,  
         R\*R\*R, G\*G\*G, B\*B\*B, R\*R\*G, R\*R\*B,  
         R\*G\*G, G\*G\*B, R\*B\*B, G\*B\*B, R\*G\*B\]  
係数を事前合成できるのは、すべての基底が同じ入力、空間、項順、正規化を使う場合だけである。後段の非線形処理、画素ごとの保護量、別種のLUTを係数行列へ無条件に含めない。違うモデルのルックは別モードで明示的に評価する。

## **8 2 混色を継続的に変えたときの挙動**

通常の重み変更では出力が連続的に変化する。全重みゼロから最初の非ゼロ重みに切り替える点は正規化比率が未定義の境界であり、単独ルックへ切り替わる。表示上は100ms以内の短い遷移を許可するが、この遷移はエクスポートの計算に含めない。

強度0から100%の操作は連続とする。係数の項順、浮動小数点の合算順はlook IDで固定し、表示順変更の丸め差を抑える。Undoで重みゼロへ戻したときは元の処理状態へ完全に戻る。

# **10 知覚補正と色の保護**

FR-PER-01 多項式出力をXYZ D65経由でOKLabへ変換し、元のルック入力の明度とクロマも保持する。広色域RGBへlinear sRGB専用行列を直接使わない。立方根は符号を保つ実装とし、非有限値を伝播させない。

FR-PER-02 明度保持は0から100%、既定0%。多項式の明度と入力明度を設定量で補間し、元のフィルム調のトーンを必要に応じて弱められる。明度保持だけを操作する場合、意図せず色相を回さない。

FR-PER-03 ニュートラル保護は0から100%、既定50%。入力のOKLabクロマが0.02以下で最大、0.02から0.08で滑らかに0へ移行するマスクを使う。クロマ差分のaとbだけを抑え、黒の持ち上げやコントラストは抑制しない。100%で灰色入力をニュートラルに保つ。

FR-PER-04 肌色保護は0から100%、既定50%。既定マスクは入力のOKLCH色相20から70度、明度0.25から0.90、クロマ0.015から0.18に滑らかな境界を設ける。顔認識ではなく色の範囲であり、木や夕景にも作用し得る。マスク表示と保護OFFの比較を提供する。

保護処理は混色ブロックが生じさせたaとbの差分に掛け、後からユーザーが行う明示的な色バランス操作には掛けない。ニュートラル保護と肌保護が重なる場合は最大の保護量を使い、順番依存にしない。保護基準は混色直前の入力画素で固定する。

FR-PER-05 ハイライト彩度保護は0から100%、既定50%。後段の彩度増加分を明度0.75から1.00で滑らかに抑える。元の彩度を強制的に0へ落とさない。灰色では色相を未定義として扱い、色相操作量を0にする。

色相の補間が必要な場合は円周上の最短経路を使う。0度と360度を離れた端点として扱わず、低クロマ領域ではaとbで処理して色相のちらつきを避ける。

## **11 1 DensityとVibrance**

Densityは画素のOKLabクロマと明度から滑らかな有彩色マスクを計算する。正方向は明度をわずかに下げながらクロマを増やし、負方向は逆にする。グレー、透明画素、極端な暗部とハイライトへの影響を弱める。

d \= density / 100.0  
colorMask \= smoothstep(0.02, 0.15, chroma)  
toneMask \= smoothstep(0.05, 0.25, L) \* (1 \- smoothstep(0.75, 0.98, L))  
m \= colorMask \* toneMask  
Lout \= L \- 0.08 \* d \* m  
Cout \= chroma \* max(0, 1 \+ 0.25 \* d \* m)  
これは初期の規範モデルで、光学的な染料濃度や顔料の分光特性を再現するものではない。画作りレビューで定数を調整した場合はエンジン版を更新する。肌の自然さと階調を評価し、Density100が常に推奨値になる設計にはしない。

Vibranceは低彩度ほど増加量を大きくし、クロマ0では0を保持する。既に高彩度の画素は増加を小さくする。肌マスクとハイライト彩度保護を増加成分だけに適用する。負方向は単調にクロマを減らし、色相を反転させない。

## **11 2 トーンとバランスの操作**

Blue YellowとGreen Purpleの最大変位は各OKLab軸0.04とし、明度の両端で弱める。WBは入力を整えるためのゲイン、これらは混色後の創作バランスとして分離する。

Pre ContrastとFilmic Contrastは黒白の順序を逆転させない単調カーブとする。Pivotは初期版でOKLab明度0.55固定。Fade100の黒上げ上限は明度0.12。Highlight Rollは0.75以上を主対象とし、白を元より暗くする場合も連続な肩を形成する。

Agingは単一の量からクロマ低下、暗部暖色、Fade増加を結び付ける。Aging0は無効果。Grainや傷を自動で追加しない。独立Fadeと重なる場合の処理順序はAgingの後に独立Fadeとする。具体カーブ定数はエンジン版に含めて固定する。

## **11 3 Nuance**

FR-NUA-01 Nuanceは時間変化するノイズではなく、再現可能な混合レシピ探索機能とする。「候補を生成」で3候補を表示し、1候補を選ぶと1回のUndo操作として現在レシピに適用する。

FR-NUA-02 amount、seed、変更対象のカードを保存する。PRNGはPCG32など版を固定したものを使い、Math.randomだけには依存しない。既定では現在有効な非ロックカードだけを変更する。「未使用色も探索」を選択した場合だけ0のカードを追加できる。

FR-NUA-03 全体強度、Exposure、WB、質感、ロックカードの重みは保持する。amount0では元レシピを返す。全カードがロックなら生成を無効化する。動画フレームごとにseedを変えない。候補のseedと確定後の重みを両方保存し、PRNG更新後も旧レシピを復元する。

# **12 色域と数値安全性**

FR-GAM-01 sRGB境界を超える色は、OKLCHの明度と色相をできるだけ維持し、境界へ近づくほどクロマを滑らかに圧縮する。設定は標準、安全、OFFを提供する。標準を既定とする。

標準モードは、すでに色域内にある無編集の画素を変えない。全基本調整が無効果で混色も恒等の場合は、出力の量子化以外で元のsRGB値を維持する。安全モードだけは色域内の高彩度域にも保護的な圧縮を許可し、その違いを表示する。

OFFは診断用で、領域外の値を保持したまま表示可否を判断する。PNGとJPEG出力は必ず対象色域へ収めるため、OFF状態からの出力で最終安全変換が入ることを示す。OFFを使っても画像出力に負値や1超の符号化値を入れない。

FR-GAM-02 色域外の可視化は圧縮前の画素を対象とする。ハイライト警告は出力符号化後の近飽和領域、黒潰れ警告は出力の近黒領域を対象とし、単なる色域外と区別する。

FR-GAM-03 LUT出力では同じ安全変換を焼き込み、入力の0から1の契約を明示する。LUT外挿の挙動はホストで異なるため保証しない。負の値やscene linearの大きい値を標準LUTへ直接入力しない。

FR-GAM-04 非有限な画素の検知時は該当処理を停止し、最後に正常だったプレビューを保持する。書き出しは失敗として返す。無言で黒画像に置き換えない。係数パック読み込み時に同じ検査を行う。

# **13 プレビューと比較**

FR-VIEW-01 Fit、100%、25から400%のズーム、パン、画面中央へ戻す操作を提供する。100%は画像1画素と表示画素の対応を説明し、OSのスケールで誤解させない。

FR-VIEW-02 Beforeは入力を向きと色空間だけ正規化した画像、Afterは現在の全編集結果とする。Beforeにも入力の色管理は行い、ICC未処理の画像との比較にしない。

FR-VIEW-03 OriginalとAfterの切替、縦横ワイプ、左右表示、AとBスナップショット比較を提供する。比較名、編集時刻、設定差分の要約を表示する。比較中も同じズームと表示範囲を使う。

FR-VIEW-04 全体バイパスとグループバイパスは一時表示で、保存設定を変更しない。出力時は確定設定を使う。比較表示、ズーム、ガイド、警告オーバーレイ、スコープ、ソロ、マスク表示は出力へ焼き込まない。

FR-VIEW-05 自動低解像度プレビューは「操作中」と表示し、操作停止後に品質を戻す。古い非同期計算結果が新しい設定のプレビューを上書きしない。計算revisionが一致した結果だけ表示する。

FR-VIEW-06 GrainとVignetteは全解像度座標を基準とする。拡大と縮小やタイル境界で模様を作り直さない。Grainはseedと座標から決まり、プレビューと書き出しの対応を保つ。

# **14 スコープと画素情報**

FR-SCP-01 P1は輝度Histogram、RGB Histogram、RGB Parade、輝度Waveform、Vectorscopeを提供する。必要なスコープを2つまで同時表示できる。

FR-SCP-02 測定段階はInput、Pre Look、Post Look、Outputを選択でき、既定Output。Outputの値はsRGB符号化RGBの0から100%で表示し、放送信号のIREと誤表記しない。P2のRec709モードで検証した場合にだけIRE表示を提供する。

FR-SCP-03 透明画素は除外する。通常プレビューは最大512pxのサンプル画像から算出して「サンプル測定」と表示する。精密測定は静止画全体から実行できる。精密計算中は操作でき、結果に設定revisionを付ける。

FR-SCP-04 ピクセルインスペクタは座標、出力RGB、linear RGB、OKLab、アルファを表示する。スコープ選択による測定空間をラベルで区別する。警告しきい値は白99%、黒1%を初期値とし、変更できる。

# **15 プリセットと履歴**

FR-PRE-01 ルックプリセットには混合、知覚保護、Creative、質感を保存する。Exposure、WB、入力プロファイルは既定で除外する。「基本補正も含む」を明示的に選べる。入力と出力の色空間が異なるプリセットは無言で適用しない。

FR-PRE-02 名前は1から80文字、説明は0から500文字、タグは最大10個。作成、複製、名称変更、削除、お気に入り、検索、JSON入出力を提供する。組込みプリセットは複製して編集する。

FR-PRE-03 プリセット適用は1回のUndo単位。素材の置き換え、クロップ、書き出し先は変更しない。画像を跨ぐコピーはルック設定だけが既定。「全設定をコピー」は色空間の一致を確認する。

FR-HIS-01 履歴は最大200確定操作／素材。新しい操作でRedo分岐は捨てる。Undo可能な項目はパラメータ、グループ有効、プリセット、Nuance、素材別ルック適用。ズーム、再生位置、選択、表示レイアウトは履歴対象外。

FR-HIS-02 AとBの2スナップショットと任意の名前付きスナップショット最大20件を提供する。スナップショットから現在設定へ戻す操作はUndo可能。アプリ再起動で全Undo履歴の保持は保証しないが、現在設定とスナップショットは保存する。

# **16 保存と復旧**

FR-SAV-01 プロジェクトはIndexedDBをメタデータ、OPFSを素材とキャッシュに利用する。OPFSが使えない環境は容量制限付きIndexedDBへ切替え、その制限を表示する。初回利用にアカウント作成を要求しない。

FR-SAV-02 確定操作から1秒の遅延で自動保存し、「保存中」「保存済み」「保存失敗」を表示する。保存revisionと編集revisionが一致するまで保存済みと表示しない。終了時イベントだけに依存せず継続保存する。

FR-SAV-03 移植用ファイルは拡張子 .cmsproj のZIPとし、manifest.json、presets、look packs、任意のmediaを収める。「設定のみ」「素材を含む」を選べる。既定は設定のみ。設定のみファイルの再読込は不足素材の再リンクを案内する。

FR-SAV-04 メディアは元バイト列のSHA256、サイズ、寸法、名称を記録する。再リンクはハッシュ一致を優先し、異なる素材にリンクする場合はユーザーの明示操作とする。素材欠落でも設定、プリセット、LUT出力は可能にする。

FR-SAV-05 保存は新revisionを準備後に参照を切替える方式とし、途中失敗で最後の正常版を壊さない。破損時は最後に検証済みのsnapshotを復元する。復元できない場合は編集結果の設定書き出しを可能にする。

FR-SAV-06 ストレージの消去やブラウザのデータ整理でローカル保存が失われ得る。設定画面に移植用保存と使用容量を提供し、容量80%で整理を案内する。永続ストレージ要求は利用可能なら実施するが、許可される前提で作らない。

# **17 静止画書き出し**

FR-EXP-01 JPEG8bit sRGBとPNG8bit sRGBを提供する。既定はPNG、元解像度、sRGB。JPEG品質は1から100、既定95。長辺指定は元寸法以下、縦横比固定を既定とする。

FR-EXP-02 PNGは透明度を保持する。JPEGは背景色を選択し、既定白。アルファの扱いによる黒い縁を防ぐ。EXIF Orientationは正規化済みの値とする。

FR-EXP-03 出力にsRGBプロファイルまたは適切な色空間タグを付ける。JPEGのEXIF、特にGPSと機器情報は既定で除去。「撮影情報を保持」を選んだ場合も位置情報は別スイッチとする。PNGも不要な文字メタデータを除去する。

FR-EXP-04 出力開始時の設定revisionを固定し、途中の編集は書き出し結果に反映しない。Progress、キャンセル、完了、保存先、失敗理由を表示する。キャンセル後に完成品に見える不完全ファイルを残さない。

FR-EXP-05 大画像はタイル処理し、Grainは全体座標、Vignetteは画像全体の中心と半径を使う。P2のBloomとHalationにはカーネルに対応したタイル余白を付け、境界線を出さない。

FR-EXP-06 書き出したPNGを同一色管理で再読込し、エンコード前の量子化済みRGBとの一致を検証する。JPEGは不可逆圧縮の誤差があるため同じ完全一致基準を使わない。出力成功はエンコーダ完了とファイル保存成功の両方が成立した状態。

# **18 LUT入出力**

FR-LUT-01 P1は .cube の3D LUTを33と65格子で出力し、既定33。33は35,937点、65は274,625点。入力領域は0から1、値は小数点以下6桁以上、Rが最速、G、Bの順で走査する。

FR-LUT-02 出力モードはLook OnlyとFull SDR。Look Onlyは混色、保護、Creative、Post調整、最終色域圧縮を含み、Exposure、WB、Pre補正は含めない。Full SDRはこれら基本補正も含む。どちらもsRGB符号化入力とsRGB符号化出力を契約とし、先頭コメントと付属JSONに明記する。

FR-LUT-03 Look Only比較は基本補正を無効果へ戻した専用プレビューで行う。通常のAfterと同じと思わせない。Full SDRはsRGB素材に対する全ポイント変換の照合に使う。ファイル名にモードと空間を含める。

FR-LUT-04 Grain、Vignette、Bloom、Halation、比較表示、リサイズ、クロップ、ローカルマスク、動画キーフレームはLUTに含められない。既定は除外項目を明示して出力し、「LUTで再現する見た目」を別プレビューできる。除外により見た目が変わることを隠さない。

FR-LUT-05 .cube単体には色空間やエンジン版の十分な標準メタデータがないため、選択した場合は .cmslut.zip にcubeとmetadata.jsonと設定を同梱する。cube単体にもコメントで最低限の契約を記載する。

FR-LUT-06 LUT生成は現在画像のサンプルからではなくRGB格子全体を同じポイント処理に通して行う。マスクが画素値だけで決まる肌保護とニュートラル保護は焼き込める。画像内容、座標、隣接画素、時間に依存する機能は焼き込めない。

FR-LUT-07 出力前に10,000点の固定検証セットで直接エンジンとLUT補間の差を測定する。最大誤差と95パーセンタイルを表示し、33で失敗した場合は65を案内する。65でも基準を超えた場合は「品質未保証」を表示し、正式な互換出力として扱わない。

FR-LUT-08 P2では17、33、65格子の外部cubeを読み込める。宣言、点数、有限値、サイズを検証し、入力と出力空間をユーザーが指定する。初期の外部LUTは共通のsRGB領域だけに適用する。ルック前後の位置を固定し、非対応の1Dと3Dの混在は拒否する。

# **19 動画の機能契約**

P2は単一クリップのSDRカラー編集を提供し、NLEのような編集機能を広げない。読み込み候補はMP4のH264とAAC、WebMのVP9とOpus。実際の提供可否はコンテナのdemuxとcodec supportを組み合わせて判定する。\[R8\]

FR-VID-01 decoder support、encoder support、音声codec、muxer、色タグを起動時とファイル選択時に検査する。WebCodecsが存在するだけで全codecが使えると判定しない。拡張子だけで対応済みと表示しない。

FR-VID-02 再生、停止、1フレーム送り、シーク、InとOutの範囲指定、音量、ミュート、静止フレーム出力を提供する。初期上限は1920×1080、60fps、10分、1GiB、1クリップ。4Kは端末評価後の追加モードとする。

FR-VID-03 初期の混合レシピとCreativeはクリップ全体で固定。プレビューのコマ落ちは許可して表示するが、書き出しでは入力PTSの順序と全対象フレームを保持する。VFRの入力を一律fpsとみなさない。

FR-VID-04 demux、decode、GPU処理、encode、muxを分離し、queueの上限を8フレームとする。VideoFrameを使用後にcloseし、長時間動画を全フレームメモリへ展開しない。decode queueのbackpressureとキャンセルを実装する。

FR-VID-05 音声は対応形式かつtrim条件が成立する場合に元codecを保持し、それ以外は対応codecへ再エンコードする。音声保持ができない場合、無言で無音にせず、開始前に無音出力を選ぶか停止する。映像PTSと音声PTSの同じ起点を保つ。

FR-VID-06 出力は利用可能なMP4またはWebMから選び、解像度、fps方針、bitrate、音声、範囲、ファイルサイズ目安を表示する。色のprimaries、transfer、matrixとfullまたはlimited rangeを検証し、double range conversionを避ける。

FR-VID-07 Grainはフレーム番号と固定seedから決める。seekし直しても同じフレームは同じ粒子となる。フレーム毎のNuance再生成、肌保護しきい値のランダム化は行わない。

FR-VID-08 HDR、10bit、H265、AV1、ProRes、RAW動画は初期の正式対応に含めない。ブラウザで再生できても、処理経路が8bitへ下げる形式は高ビット深度編集と表示しない。

# **20 拡張機能とResolve連携**

FR-EXT-01 P2の領域別ミキサーはShadow、Midtone、Highlightごとに同じ12基底を使う。入力OKLab明度から連続な重みマスクを作り、3マスクの和を1に保つ。各領域の比率は独立正規化し、ゼロの領域は恒等変換とする。

領域別の3行列は設定変更時に合成できるが、画素ごとの領域マスクを単一の一定行列へ合成できない。画素値だけによる領域分離ならLUTに焼き込める。操作境界の段差は受入試験で禁止する。

FR-EXT-02 P3は混合重み、全体強度、Exposure、Creativeのキーフレームを提供する。補間は初期linear、固定値はhold。seed、codec、色空間、look pack IDのような離散設定は連続補間しない。LUT出力は指定時刻の固定設定だけを評価する。

FR-RES-01 P1のResolve連携はLUTの手動読み込み手順に限定する。sRGB素材をsRGB入力と出力のノード領域で扱う契約を示し、タイムラインのRec709 Gamma2.4やDWG Intermediateへcubeを直接適用しない。

FR-RES-02 P3のDCTL出力は独自ポイント処理のみを対象とし、WGSLとCPU参照と同じ定義から生成する。Grain、BloomなどをLUTで移せないという理由だけでDCTLで必ず移せると約束しない。DCTLの実行モデルに適合する処理だけを含める。

FR-RES-03 ローカル補助サービスはユーザーが明示的に有効化する。localhostにbind、ランダムtoken、Origin検査を要求し、任意コマンド実行APIを持たせない。ブラウザからファイルシステムやResolveを自動探索しない。

FR-RES-04 補助サービスの最初の対象は、接続状態、対象プロジェクトとクリップの確認、LUT配置、適用の明示操作、成功と失敗の表示とする。Resolveの対応版とScripting APIを実機検証してから提供する。全パラメータの双方向同期は初期対象外。

# **23 性能と対応環境**

製品の保証はブラウザ名だけでなく、検査済みの経路で決める。WebGPU不可時はP1のCPU Worker経路で低解像度プレビューと画像出力を提供し、低速であることを表示する。WebGL2経路は任意の最適化とし、機能や色の定義を変えない。

| 指標 | P1の受入目標 | 測定条件 |
| :---- | :---- | :---- |
| パラメータ応答 | 95%が50ms以内 | 長辺2048px、Grain OFF、スコープOFF |
| 操作中の表示 | 30fps以上 | 必要なら長辺1024pxへ低減 |
| CPUプレビュー | 確定後500ms以内 | 長辺1024px、参照PC |
| 初回プレビュー | 24MP JPEGで5秒以内 | 既に起動済み、ローカル読込 |
| LUT33出力 | 2秒以内 | 固定レシピ、品質検証を除く |
| LUT65出力 | 5秒以内 | 固定レシピ、品質検証を除く |
| 原寸PNG出力 | 24MPで15秒以内 | GPU経路、同時動画処理なし |
| メモリ | 24MPの1素材で512MiB以下を目標 | decodeからexportまでのピーク |

参照PCはApple SiliconのMac、メモリ16GB、およびWindows PC、メモリ16GB、対応GPUとする。具体機種、OS、ブラウザ版、shader設定は試験報告に記録し、上記数値を全端末保証と表示しない。

GPU資源が失われた場合は1回再作成を試し、失敗時はCPU経路へ移る。編集設定は保持する。書き出し中なら失敗または最初から再実行とし、複数経路の途中結果を混ぜない。

通常モードはHDRモニターでもSDR表示として扱う。Display P3の表示と出力はP2で経路を検証する。画面のICC、OSの色管理、ディスプレイの設定による差は、同じ数値RGBが全モニターで同じ見た目になる保証とは分離する。

# **24 操作性とアクセシビリティ**

デスクトップ推奨幅1280px以上、900から1279pxでは左右パネルを可変幅、900px未満では素材、プレビュー、調整のタブへ切替える。狭い画面でも出力、Undo、比較へ到達できる。

全入力にラベルと現在値を付け、色だけで有効無効や警告を区別しない。キーボードで全スライダーと出力へ到達でき、フォーカスを視覚表示する。ダイアログではフォーカスを閉じ込め、閉じた後に元へ戻す。

ショートカットはCmdまたはCtrlとZでUndo、ShiftとZでRedo、Oで読込、Sで保存、Eで出力。入力欄の編集中は文字入力を優先する。単独のBでBefore切替、FでFitを行うが、入力欄では発動させない。

日本語と英語を提供し、初期言語はブラウザ設定、変更を保存する。色名と内部IDは翻訳で変えない。数値は内部では小数点の統一形式、UIはlocaleに合わせる。完了と失敗はスクリーンリーダーへ通知し、30fpsの更新を読み上げない。

# **25 エラーとセキュリティ**

| コード | 条件 | ユーザーへ提供する回復操作 |
| :---- | :---- | :---- |
| E\_FORMAT | 非対応形式と壊れた素材 | 対応形式と変換案内 |
| E\_PROFILE | 未知ICCと未指定Log | プロファイル指定またはsRGB変換 |
| E\_SIZE | 上限とdecode寸法超過 | 縮小素材で再読込 |
| E\_MEMORY | メモリとGPU制限 | 解像度低減、素材を閉じる |
| E\_GPU | デバイス喪失 | 復旧、CPU経路、設定保存 |
| E\_STORAGE | 容量と保存失敗 | 移植用ファイルを出力、キャッシュ整理 |
| E\_SCHEMA | presetとprojectの不正 | エラー箇所と対応版の案内 |
| E\_PACK | 欠落係数とchecksum不一致 | 対応パックの再読込 |
| E\_CODEC | encodeまたはdecode不可 | 対応形式、静止フレーム出力 |
| E\_EXPORT | encoderと保存の失敗 | 別形式、再実行、設定保存 |
| E\_CONFLICT | 別タブのrevision競合 | 読取専用、再読込、別名保存 |

ZIPはパスの正規化、階層制限、展開後の総サイズ上限を設け、../や絶対パスを拒否する。最大2000entry、展開合計2GiB、manifest5MiBを初期上限とする。構造検査前に大量のメディアを展開しない。

プリセット、project、look packはコードとして実行しない。初期カスタムshader読み込みは提供しない。製品自身のアセットは固定したCSPの下で配布し、画像や動画を解析目的で外部送信しない。

テレメトリは既定OFF。ONでも素材、ファイル名、サムネイル、GPS、設定レシピを送信しない。アプリ起動中のネットワーク送信先と用途は設定に表示する。オフライン編集はアプリ資産が事前に取得済みの場合に提供する。

# **26 受入試験と品質ゲート**

次の数値は本アプリの受入目標であり、元製品の性能値ではない。CPUはfloat64参照、GPUはfloat32で測る。RGB誤差はlinear sRGBで評価し、知覚差はD65のOKLabユークリッド距離に100を掛けたDelta E OKとする。CIEDE2000と同じ値として扱わない。

| T02 | MIX | 強度0、その他無効果 | 混色ブロックは恒等変換 |
| T03 | MIX | 1色で重み1と100 | 出力差1e-5以下 |
| T04 | MIX | 30と70、60と140を内部で比較 | 正規化後は差1e-5以下 |

| T06 | MIX | 強度0から100を1000段階 | 異常な不連続と非有限値なし |
| T07 | PER | 灰色ランプ、Neutral100 | aとbの各絶対値1e-4以下 |
| T08 | PER | 複数肌色と夕景、保護量を変更 | マスク境界の段差なし、誤保護を確認 |

| T14 | SAV | 保存、再起動、再リンク | 設定値と係数版と表示結果が一致 |

T04はUIの100上限を超える内部の正規化計算試験。T11は対象ホストの三線形補間と四面体補間を分けて記録し、いずれでも合格する設定を正式な互換出力とする。格子点そのものだけの照合で補間品質を合格にしない。

検証セットは同じseedのRGB格子内ランダム点、黒白のランプ、赤緑青と補色のランプ、低クロマ、肌色域、0と1の近傍を含む。連続性評価は全重みゼロ境界の仕様上の切替えを除く。自然画像は権利を確認した人物、屋外、室内、ネオン、低照度、風景、製品写真を含める。

創作ルックの視覚受入は、全12単独ルック、66組の2色50対50、代表的な3色、全12均等混合について行う。目標は意図しない肌の緑化、白の蛍光色化、黒の色相反転、階調バンディングを排除すること。好みの違いを不具合と混同しないよう、事前に承認したターゲット画像と照合する。

P1リリースはT01からT19、T23とT24に合格し、12ルックの視覚承認、対応ブラウザ試験、LUT品質検証を完了する。P2はT20とT21、P3はT22を追加する。基準未達の項目はリリースノートに残すだけで正式機能へ昇格させない。
